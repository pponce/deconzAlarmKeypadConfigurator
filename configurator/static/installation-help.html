Administration

Connect your gateway

Choose your installation

  1. Local deCONZ without Homebridge: generic administration on the deCONZ host. No Homebridge installation or helper is required.
  2. Local deCONZ with local Homebridge child bridge: all three run on the same Linux machine. Setup verifies the existing child bridge, unrestricted user, local credential database and service-control executable.
  3. Remote deCONZ without Homebridge: enter the other machine’s gateway URL. Setup checks its identity, enhanced capabilities and live-event WebSocket. Homebridge is not inspected or configured.

The remaining combinations, including remote Homebridge and remote deCONZ with local Homebridge synchronization, require a future remote agent and are not offered by this installer.

Required deCONZ build

Currently this configurator works only with the enhanced pponce/deconz-rest-plugin fork, alarm-users-v1 branch. Stock deCONZ is not supported. Setup checks the bridge identity and enhanced global-user capabilities before accepting a connection.

Install the compatible plugin separately on the deCONZ host, following that repository’s build instructions. The configurator does not install, upgrade or restart deCONZ.

Discovery and manual connection

Setup checks ports 80 and 8080 on the configurator’s Linux server. For a remote gateway or custom port, enter its complete URL under Connection options, then choose Check gateway address. For example: http://192.168.1.20:8080. The gateway must be reachable from this server.

Remote gateway connectivity and backups

Allow both the REST port in your URL and the gateway-advertised WebSocket port from the configurator server. Use a trusted LAN or VPN. HTTP gateways use WS; HTTPS gateways require a trusted certificate and WSS on the advertised event port. HTTPS verification is not disabled.

Remote setup saves policy snapshots here; back up the deCONZ database on its own host. Confirm that backup arrangement in the installer. An uncertain credential write remains held for administrator-assisted recovery: there is no remote database verifier in this release. Do not retry the write or delete its journal.

Finding or creating a deCONZ API key

An API key is the value called username in a successful API-key creation response. Use that saved response or your private saved copy if you already have a dedicated key. It is different from your Phoscon login password, configurator password and alarm PIN. The configurator never displays a stored key. If your existing connection works, leave Replacement API key blank.

During first installation · recommended

  1. When the terminal wizard asks whether you have an existing API key, answer No if you do not have one.
  2. Open the selected gateway’s Phoscon app and choose Settings → Gateway → Advanced → Authenticate app.
  3. Within 60 seconds, return to the terminal wizard and confirm Connect now. The wizard requests and saves a dedicated key automatically; you do not need to copy it. In browser setup for a new connection, use Connect and create API key instead.

Replacing a key for an existing connection

The replacement field accepts a key you already obtained; it does not create one. Do not rerun the fresh installer or add a duplicate gateway to replace a key.

  1. Open that gateway’s Phoscon app, then choose Settings → Gateway → Advanced → Authenticate app.
  2. Within 60 seconds, use a REST client to send POST /api to the same gateway URL and port shown under Connections, with content type application/json and body {"devicetype":"alarm-configurator"}.
  3. From the successful response, copy only the string in success.username into Replacement API key, then select Verify and save connection. Keep the key private.
  4. Follow the connection activation notice. Do not revoke keys used by Homebridge or other applications.

Authenticate app opens an authorization window; the API response supplies the new key. If a request’s result is uncertain, review it before sending another creation request.

During guided enrollment, a saved key is reused after a compatibility failure. An uncertain creation result remains held for review; do not delete its receipt or repeatedly create keys.

Optional Homebridge

The guided terminal installer can register an existing Homebridge installation on the same Linux host. It checks the supported homebridge-deCONZ package, child bridge, selected alarm accessories, unrestricted API user and cached credential. Homebridge login details are not deCONZ API keys.

Install Homebridge and configure its deCONZ child bridge first. Initial synchronization registration currently needs a local deCONZ database for independent credential verification. For a remote gateway or a newly unenrolled alarm, skip synchronization and use the generic interface. Remote Homebridge and Docker are deferred.

Homebridge-deCONZ installation and configuration help

No Homebridge restart or PIN change is performed during onboarding. Later credential changes use coordinated maintenance and may require extension-specific steps.

Fresh install versus existing installation

The guided installer is for a fresh Linux systemd installation. It refuses an existing configurator. Existing users continue directly into administration and are not forced through first-run setup.

The installer opens a private browser setup session to collect the administrator password, connection details and listening address (HTTPS port 9443 by default), verify them, then install and start the application. A terminal-only option remains available. It presents a local self-signed HTTPS certificate valid for 90 days. Certificate renewal and reverse-proxy deployment require administrator configuration; they are not automated yet.

Connection edits in the gear settings still require controlled broker activation. Do not run the fresh installer over an existing installation to apply them.
