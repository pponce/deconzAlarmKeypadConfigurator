About your deCONZ API key and how to obtain one

This application currently requires the enhanced pponce/deconz-rest-plugin · alarm-users-v1 build. Stock deCONZ is not supported.

Homebridge

Homebridge is optional. Generic user, alarm and keypad administration works without it. The supported integration uses a local deCONZ child bridge. Initial registration and protected host paths are configured by the Linux installer; select its alarm user later in Users.

Preferences & sign-in

Your administrator username and password were created in the installer. You can change it later using the gear icon → Security. It is separate from your deCONZ API key and alarm PINs.

Refreshes alarms and keypads already known to your configured gateways. It does not pair devices or scan your network.

Controls browser updates. Background live-event collection runs independently of both refresh intervals.

Before your first change

Users and PINs belong to a gateway. Permissions, schedules and remaining uses belong to each alarm. First enrollment is an explicit action in the user editor; setup does not enroll alarms automatically.

Policy snapshots are retained before edits. Without a verified local database backup, arrange credential backups on your deCONZ host.

The virtual keypad sends real alarm commands. Use it only when you intend that action.
