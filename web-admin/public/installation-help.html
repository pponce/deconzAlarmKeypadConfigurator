Start and connect

Run npm run setup in the standalone project to choose your HTTPS address, connect a deCONZ gateway and create the first web administrator. Then run npm start. Homebridge is optional. This server does not control garage doors or bolts.

Web accounts sign in to this interface. They are separate from deCONZ alarm users, alarm PINs, Homebridge accounts and Phoscon accounts. Administrators can add web accounts in Settings → Security.

deCONZ connections and keys

The deCONZ API key authenticates this application to deCONZ. Existing keys are kept privately and never displayed here. To create a dedicated key, open Phoscon → Settings → Gateway → Advanced → Authenticate app. Within that authorization window, send an HTTP POST to your deCONZ URL followed by /api, with Content-Type application/json and body {"devicetype":"deconz-keypad-admin"}. Copy the returned success.username into the API-key prompt or connection form.

Edit an existing gateway in Settings → Connections. Leave the replacement key blank to retain it. The server verifies the saved gateway identity before accepting a change. Restart the standalone server to activate it. While activation is pending, gateway actions are held. To add another gateway, stop this server and run node bin/deconz-keypad-admin.js gateway, then start it again.

User administration requires the enhanced deCONZ managed-users API, including global_users_version: 2. An ordinary deCONZ installation without these endpoints cannot provide these features.

HTTPS and LAN access

The server generates its own private self-signed certificate. Trust that certificate separately for direct browser use. The default address is https://localhost:9443, listening only on the local machine. To use another computer, stop the server and run node bin/deconz-keypad-admin.js network. Enter the server’s LAN HTTPS address and select 0.0.0.0 as the listening address. Use exactly the configured browser address.

Users, access and the virtual keypad

Names, PINs and enabled status apply across a gateway. Access grants, keypad permissions, schedules and use allowances apply to each selected alarm. Keep an unrestricted owner for every managed alarm.

The virtual keypad sends alarm commands directly to deCONZ. It needs neither Homebridge nor a controller. Physical keypad lockout rules do not also rate-limit the API keypad.

Optional Homebridge PIN synchronization

For a local Linux Homebridge installation, stop this admin server and run node bin/deconz-keypad-admin.js homebridge. Provide its storage directory, config.json path and installed homebridge-deconz package directory, then restart this admin server. Use the same operating-system account as Homebridge so it can access the targeted saved accessory data.

The current adapter supports one deCONZ child bridge and a local HTTP Homebridge UI. It checks the reviewed homebridge-deconz 1.3.5 and homebridge-lib 8.1.5 source fingerprints. Changed versions require a compatibility review. Remote Homebridge and an HTTPS-only Homebridge UI are not supported by this adapter.

Choose the Homebridge user and included alarms under Users. A PIN update asks for explicit restart confirmation and a Homebridge administrator login. The deCONZ child bridge stops, its alarm PIN is updated, and it restarts. This web server remains available. Homebridge login credentials are not saved.

Interrupted changes

Follow the saved recovery steps if a response is lost. Do not repeat the change automatically. Policy snapshots exclude PINs. An uncertain credential write can require separate verification; there is no automatic force-release or replay.

When using a custom data directory, pass the same --data-dir PATH with every command. See the repository README for setup and extension development details.
